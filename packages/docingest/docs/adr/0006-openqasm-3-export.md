# ADR 0006: Export a paper's circuits as OpenQASM 3

**Status:** proposed, 2026-10-22; revised 2026-11-13 to put the emitter behind a port

## Context

`gate_list(source)` reads a circuit drawn in a paper's LaTeX and returns it as data:
`CircuitSteps`, with `GateOp` items, the sides of a drawn equality as parts, and wire 1 at the
top. `CircuitSteps.to_dict()` is the `circuit/1` format that the separate
[`quantum-sim`](../../../quantum-sim/README.md) package reads. That format is good for a
simulator and for an agent, but it is not a program: it cannot be handed to a quantum SDK, a
hardware provider or another tool.

OpenQASM 3 is the portable text format for that job. The first version of this exporter lived in
`docingest.domain.qasm` and interpreted labels, controls and angles itself. That duplicated the
simulator's reader and let the two disagree: a circuit the simulator refused could be marked
`"ok"`, an open control became a closed `cz`, `R_z(\frac{1}{2}\pi)` lost its angle, and the
output used names such as `rzz` and `sxdg` that `stdgates.inc` does not define. The exporter is
now downstream of the simulator's reader instead of beside it.

## Decision

1. **The simulator owns the emitter.** `quantum_sim.qasm.to_qasm(document, *, values=None,
   origin="", tool="quantum-sim")` takes a `circuit/1` document, calls
   `quantum_sim.formats.from_gate_list(document)`, and writes only what that reader accepted. It
   does not read LaTeX again and does not interpret a gate, a control or an angle on its own. A
   document the simulator refuses is refused here, with the simulator's reasons.
2. **The dependency is one-way and lives in one adapter.** `docingest` depends on `quantum-sim`;
   `quantum-sim` never imports `docingest`. `docingest.domain.qasm` is gone. The application
   depends on the `CircuitExporter` port in `docingest/ports/qasm.py`; the only implementation,
   `docingest/adapters/qasm.py`, calls `quantum_sim.qasm.to_qasm(circuit.to_dict(), ...)`; an
   import-linter contract keeps every other module of docingest from importing `quantum_sim`. The
   adapter is imported lazily by `bootstrap.Container.qasm_export`, so a command that never
   exports a circuit, `docingest --help` included, does not load `quantum_sim` (a subprocess test
   checks it). The claim is about `quantum_sim` only: the CLI loads numpy anyway, through
   `entrypoints/bench_cli.py`.
3. **One program per part, all-or-nothing per document.** A drawn equality has several sides;
   each side is a separate program, and the drawn sign is written as `// sign: <sign>`. The first
   part has no sign. The simulator's reader is all-or-nothing: if it refuses one part, the whole
   document is refused and no program is marked `"ok"`. `QasmExportService` still writes the
   other documents and circuits in the same run, and reports every refusal.
4. **On-demand export, not ingest-time mutation.** `application/qasm.py` (`QasmExportService`)
   reads stored documents, finds their fenced `latex` blocks, delegates each circuit to the
   `CircuitExporter` port and writes the files. `docingest circuits export` drives it.
   `ingest --qasm` and `crawl --qasm` are optional hooks that run it on the documents a run just
   stored, best effort, after the store is written. A document is exported once per run (identical
   files share a `doc_id`), and a variant (`--ocr-all`, `--max-pages`) gives way to the document
   the corpus serves when that is the canonical document or a longer variant, because both would
   write the same file names; otherwise the variant the run stored is exported. No manifest,
   cache key or
   store layout changes: the output can always be made again from `document.md`.
5. **Output directory.** The files go to `<output_dir>/qasm/` by default, or to `--out DIR`. That
   directory is a sibling of the document folders, so `DocumentStore.corpus()` ignores it: it has
   no `manifest.json`. A file is named
   `<doc_id[:16]>-b<block:02d>-c<circuit:02d>-p<part:02d>.qasm`, where the block and circuit are
   1-based positions in the Markdown. After a document is exported, its files of that form that
   the run did not write are removed (a refused circuit, a lost part, circuit or block), and the
   count is reported; other documents, other files and a document whose Markdown cannot be read
   are left alone. Files get the permissions of a normal write (`0o666` minus the umask).
6. **Deterministic text.** UTF-8, LF line endings, one trailing newline, no timestamps, no
   absolute paths. The same document and options give byte-identical files.

## Output contract

```text
// Generated by <tool> (qasm format 1)
// source: <source name>, block <b>, circuit <c>, part <p>/<n>
// sign: <sign>                                  (only when the part has a drawn sign)
// bound: <name> = <value>                       (one line per binding of a symbol of this part)
// wire 1 (top) = q[0]; the simulator reads it as the most significant bit
// c[i] holds q[i]; c reads c[n-1] ... c[0], so wire 1 is its rightmost bit   (only with c)
// bit[n] declares one classical bit per wire, not only the measured ones    (only with c)
// wires: <wire legends>                         (only when a legend is not blank)
OPENQASM 3.0;
include "stdgates.inc";
qubit[<n>] q;
bit[<n>] c;                                     (only when a part measures)

<operations>
```

Wire `i` of the drawing (1 at the top) is `q[i-1]`, and the exporter never reorders wires. The
header states the two orders a reader must not confuse. The simulator writes a basis label with
wire 1 first (the most significant bit). OpenQASM 3 reads a bit register as a bit string from
`c[n-1]` down to `c[0]` (`c[0]` is the least significant bit), so in a printed value of `c`
wire 1 is the rightmost character, the simulator's label reversed. A measurement writes
`measure q[i] -> c[i];`; when any wire is measured the program declares one bit per wire. No other
item allocates a bit, and a program without a measurement has neither `c` nor its two header
lines.

A `// bound:` line names the symbol as the reader spells it (`theta_1`, never the caller's key)
and appears only in the programs of parts that use the symbol; its value is the caller's text on
one line, with every line break replaced by a space. A provenance text is flattened the same way,
so nothing a caller passes can start a line of its own.

## Gate mapping

| Drawing | OpenQASM 3 |
|---|---|
| one-qubit `gate`: `I`/`id`, `H`, `X`/`NOT`, `Y`, `Z`, `S`, `S†`, `T`, `T†`, `√X` | `id`, `h`, `x`, `y`, `z`, `s`, `sdg`, `t`, `tdg`, `sx` |
| `√X†` | `inv @ sx`; `stdgates.inc` has no `sxdg` |
| one-qubit `gate` with an angle: `R_x`, `R_y`, `R_z`, `P(...)` | `rx`, `ry`, `rz`, `p` |
| `swap`, and an `x` item on a control and a target | `swap`, `cx` |
| `x` (X on a target) | `x`; closed controls become `cx`, `ccx`, or `ctrl @ ... @ x` |
| `z_dots` | `cz` for two dots, otherwise a controlled `z` |
| closed control | a `\|1>` control; one control uses `cx`/`cz`/`cswap`, two use `ccx` for X, more use `ctrl @ ... @` |
| open control | `x` on the control before and after the operation; exact for every gate |
| `measure` | `measure q[i] -> c[i];` |
| `barrier` | nothing: the simulator's reader treats it as a non-operation |
| `text` | `\|0>` is an input marker; `\|1>` at an input refuses the document; any other text is refused |
| `sign` | refused: a sign drawn on a wire is not an operation |

Gates the simulator knows but `stdgates.inc` does not define are refused in qasm format 1:
`rxx`, `ryy`, `rzz`, `rk` and `iswap`. Writing them would need an exact decomposition into
standard gates (`rzz` as `cx`, `rz`, `cx`, for instance). That is a separate decision, with its
own tests against the simulator, and it is not planned in this change; until then a refusal is
better than a guessed program. A controlled standard gate is written
with its standard controlled name where one exists (`cx`, `cy`, `cz`, `ch`, `cp`, `crx`, `cry`,
`crz`, `cswap`, `ccx`), and as `ctrl @ ...` otherwise.

Parameters are the simulator's angle trees, so the program says what the drawing said. A free
symbol is refused unless the caller binds it with `values` / `--set`; nothing is evaluated to a
rounded decimal. Every number is written as a float literal, because OpenQASM's `/` on two
integers is integer division and an int-to-angle cast is not allowed:
`R_z(\frac{1}{2}\pi)` becomes `rz((1.0/2.0)*pi)`, `R_y(5.)` becomes `ry(5.0)`, and
`2^3` becomes `2.0**3.0`. A binding value may be written as `pi/4` or `\pi/4`: a text value is
read by `quantum_sim.angles.parse_value` (the angle grammar, after a `pi` that stands alone
becomes `\pi`), the one value rule that the export, `run`, `check` and both `--set` options
share, so the research API's `/circuits/run` and `/check` take the same values. Its name is one
symbol of the angle grammar, by `quantum_sim.angles.symbol_name`, the one name rule that they
share too (`theta`, `\theta` and `{\theta}` are `theta`, `\theta_{1}` is `theta_1`). A
name that is not one symbol (`thetta`, `pi`, `e`, `the{ta}`, `\\theta`, a name with a line break
inside it; white space around a name is ignored) is a usage error, as are a name bound twice in two spellings, `True`, a value with a free symbol
and an integer too large for a float. A name that is one symbol but that no exported circuit
uses is a warning. A binding written as text follows the angle grammar, so it takes no
exponent notation: write `10000000000`, not `1e10`. Each bound angle is evaluated as the
simulator evaluates it, and an angle that is undefined at the bound values
(`\frac{\pi}{\theta}` with `theta=0`, `\sqrt{\theta}` with `-1`, `\theta^{-1}` with `0`,
`\theta^{64}` with `10000000000`) refuses the part with the simulator's reason, so the export
never writes a program the simulator would refuse to run.

Refused as a whole document, never skipped: a circuit whose `status` is not `"parsed"`, an
`unparsed*` item, `phase`, `dots`, `dots_gate`, `discard`, `control`, `sign`, an unknown kind, a
`classical` item, a wire outside the circuit or named twice in one item, a gate and its wire count
that disagree, an ambiguous box label (`CNOT`, `U`, `R_k`, ...), a one-qubit box drawn over
several wires, `rxx`/`ryy`/`rzz`, an input drawn as `|1>`, and a bound angle the simulator cannot
evaluate.

## Consequences

- `openqasm3[parser]` is a development dependency of `quantum-sim` only. Every golden program and
  a deterministic property test are parsed in `packages/quantum-sim/tests/test_qasm_contracts.py`; neither
  package depends on the parser at runtime.
- `docingest` now depends on `quantum-sim`. The dependency is one-way and the import-linter
  contract records it. The alternative, a second reader in docingest, is what let the two
  disagree.
- The export is read-only with respect to the store. Cached results do not change, and a document
  that is re-ingested keeps its cache identity. Removing or editing a `.qasm` file costs only a
  re-export.
- A consumer that needs bound parameters must pass them. The emitter refuses an unbound symbol
  rather than choosing a value.
- The output is one program per part, not one program per drawing. A consumer that wants the whole
  identity has to read the files together, in part order.
- An open control doubles the operation count (`x`, the gate, `x`). This is exact and needs no
  decomposition of the gate itself.
- There is no QASM reader. Importing QASM back into `circuit/1` is a separate decision with its own
  grammar and refusal rules.
- `ingest --qasm` and `crawl --qasm` never change the exit code of the ingestion. A refused
  circuit or an unwritable output directory is a warning; the papers are already stored. The
  hook passes no `--set` values, so a circuit with a free symbol is refused there, and its
  programs from an earlier `docingest circuits export --set ...` are removed as stale; the
  warning names the circuit and the symbol, and the same `circuits export --set` writes them
  again. The hint is given only when a missing value is what refuses the circuit: the adapter
  exports it a second time with a placeholder value for each symbol without a value, and
  reports their binding keys (`QasmExport.unbound`, `theta_{12}` for `\theta_{12}`) only if
  that export is ok. Each symbol gets its own placeholder (0.37 plus a tenth of the square
  root of a prime, in sorted symbol order), so
  `\frac{1}{\theta - \phi}` with neither bound still gets the hint. A circuit refused for
  another reason too (a `|1>` input, an `iSWAP` or `R_{zz}`, a value of the caller's that the
  angle cannot take) has no hint; a circuit singular at the placeholders (`\sqrt{\theta - 1}`,
  as they are below 1) loses the hint, never gains a false one.
- A file that cannot be written stops the export of that document only. The error is reported
  per document (`QasmExportReport.errors`), the document's earlier programs are kept (its cleanup
  is skipped), the other documents are exported, and `docingest circuits export` exits 1, also
  with `--allow-partial`. An error in the cleanup is reported with the number of files it
  removed; an output folder that cannot be made is one error for the run, and the run stops.
  `QasmExportReport.documents` counts the documents the run reached (one whose Markdown could not
  be read counts; those after the folder error do not), and a run with an error gives no
  "matches no symbol" warning, because a document it did not finish may use the key. A paper
  whose Markdown could not be read is a warning, not an error: the "matches no symbol" warning
  is still given (it speaks of the exported circuits), next to the "cannot read" warning.

## Alternatives considered

- **Keep the emitter in docingest with its own reader.** Rejected: it duplicated the simulator's
  label, angle and control rules and exported programs the simulator refused or misread.
- **Put the emitter in quantum-sim but leave docingest independent.** Rejected: two consumers
  would have to reproduce the `circuit/1` bridge, and the two copies could drift apart, as the
  emitter's own reader in docingest did.
- **Write the files during ingest** next to `document.md`. Rejected: the store would gain files it
  did not have, the cache key would have to cover them, and a failure would make an otherwise good
  ingestion look failed.
- **Export only `circuit/1` JSON.** Rejected: the format is useful for the simulator but is not a
  program for an SDK or a provider.
- **Depend on Qiskit to write QASM.** Rejected: a large package for one text projection, and its
  output would change with its version. The simulator is a dependency for reading `circuit/1`, not
  a reason to add a second quantum SDK for writing it.
- **Emit `reset`, `if`, or `U` gates.** Rejected for v1: the IR does not carry the information, or
  `stdgates.inc` has no exact spelling. Refusing is better than a program that means something
  else.
